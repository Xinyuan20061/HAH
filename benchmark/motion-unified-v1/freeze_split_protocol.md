# 独立受试者冻结分组方案（motion-unified-v1）

> 状态：**协议草案，待实现确认**。视频采集/授权与新标注完成前，本方案只规定分组规则与
> 冻结动作；不得在 REHAB24-6 120 段上跑出"新方案独立集指标"。

## 1. 为什么必须新冻结集

- REHAB24-6 120 段（受试者 7/8/9，六类 × 20 段）已被 `motion-v1`、`motion-v2-kinetics`
  两轮开发与阈值试探使用；其分布、机位、光照已"被看见"。规格第 9 节明确：它**不能再当
  新模型最终独立测试集**。
- 新决策门（规格 4.5）的上线阈值（接受/拒识边界、DeepSeek 复核触发条件）必须由一份
  **从未参与调参**的受试者集合决定。

## 2. 数据用途分层（受试者级隔离）

| 层 | 用途 | 受试者要求 | 可否再进独立测试集 |
| --- | --- | --- | --- |
| 历史开发集 | REHAB24-6 受试者 7/8/9 全部 120 段 | 已用于规则开发、Kinetics 候选层对照 | **否**，永久留作历史基线/回归 |
| 开发/调参集（dev） | 新采集或新授权的受试者 D1..Dk，用于调决策门阈值、提示词、评价器参数 | 受试者不得出现在测试集 | 否 |
| 独立测试集（test） | 受试者 T1..Tm，冻结后只准跑一次主口径 | **与 dev、历史集零受试者重叠** | — |
| 未知/非锻炼组（held-out negative） | 至少一组：产品目标子集之外的动作 + 非锻炼生活片段 | 同样不参与任何调参 | 计入 test 的拒识考核分母 |

硬性规则：

1. **受试者（subject_id）是最小隔离单位**。同一受试者的所有片段、所有机位、所有实例
   必须整体落在同一层；禁止把同一人的正面片段当 dev、侧面片段当 test。
2. 同一动作实例的多机位文件（如 c17/c18）必须同层、同组。
3. 新集采集前先写 `manifest_frozen.json`（含 subject_id、instance_id、video_path、
   license_record、consent_status、目标类别、是否未知组），双人标注完成后计算清单
   SHA-256 并封存；**封存后不得增补片段再跑指标**。
4. 冻结 seed：`healthmate-unified-v1-freeze`（与既有 `prepare_semantic_dataset.py`
   风格一致；（待实现确认）具体拆分脚本随 P0-B 落地时复用/扩展）。

## 3. 独立测试集组成（建议配额，待采集确认）

> 配额为建议下限；最终以实际合法授权样本数为准，样本量不足时报告必须如实写"未达建议下限"，
> 不得用演示片段凑数。

| 组 | 内容 | 建议样本量 | 考核什么 |
| --- | --- | --- | --- |
| S1 六类已见动作 | squat / pushup / lunge / leg_abduction / arm_abduction / arm_vw，新受试者、正面+侧面双机位、标准与常见错误动作混合 | ≥ 60（六类各 ≥10） | 六类识别全样本准确率、逐类召回、次数/角度评分 |
| S2 产品相关 400 类目标子集 | 从 Kinetics-400 中选定**与产品定位相关**的目标类清单（见第 4 节），每类 ≥3 段、新受试者 | 目标类数 × ≥3 | Top-1/Top-5、混淆、分机位 |
| S3 类外未知动作 | 目标子集**之外**的 Kinetics 类（产品不承诺支持的动作），≥20 段 | ≥20 | 类外误报率；正确应拒识或标 unknown |
| S4 非锻炼片段 | 走路、坐下、吃饭、看手机、聊天等生活视频，≥15 段 | ≥15 | 非锻炼拒识；不得硬套成某锻炼动作 |
| S5 质量压力片 | 低光、遮挡、多人、无完整动作周期，≥15 段（可与 S1/S3 重叠标注 strata） | ≥15 | 应拒识/uncertain 召回；防"靠拒识刷准确率" |

## 4. 400 类目标子集与未知类定义（草案，待产品确认）

- **目标子集（target_subset）**：只声明"产品打算覆盖"的类，例如（草案，待产品/答辩口径确认）：
  深蹲、俯卧撑、箭步蹲、侧卧抬腿、侧平举、臂屈伸类，以及开合跳、跳绳、原地慢跑、
  瑜伽拉伸、太极、仰卧起坐、拳击空击、骑车等常见居家/轻健身动作。
  目标子集必须以清单文件形式冻结（`target_subset.json`，（待实现确认）随 P0-C 落地），
  未列入清单的 Kinetics 类一律视为"类外未知"。
- **未知类（unknown / out-of-set）**：
  - 类别未在目标子集内；或
  - 关键证据不足（usable_frames<3、无完整周期、多人）；或
  - 本地/Kinetics/DeepSeek 三方意见冲突。
  以上三种情况统一落到 `uncertain` 或 `abstained`，**不得输出伪 label**。
- 400 类整体声明必须有相应完整数据支撑；在 S2+S3+S4 数据齐全前，对外只说"
  对目标子集做融合识别"，禁止宣称"400 类均可识别/均可评分"。

## 5. 冻结动作（checklist）

- [ ] 新受试者招募与授权文本留存（consent_status、license_record 逐条登记）（待实现确认）
- [ ] 写定 `manifest_frozen.json` 初稿
- [ ] 双人独立标注关键事件、类别、reps、应否评价、strata；第三人复核分歧
- [ ] 冻结标注后计算 manifest SHA-256，写入 `benchmark-results/motion-unified-v1/`
- [ ] 记录 pipeline_version、MediaPipe 版本、SlowFast/Kinetics 权重 SHA-256、DeepSeek 模型名与 prompt 版本
- [ ] 封存前跑一次 dry-run 格式校验（不看指标），确认 predictions 管线可跑通
- [ ] 之后才允许在 test 上跑四臂消融；dev 上可反复调参，test 主口径只跑一次
