# HealthMate 项目审计与改进记录

日期：2026-09-20

## 一、严格审计结论

HealthMate 当前已经是工程完成度较高的运动健康原型，强项是云端任务队列、本地 AI Worker、媒体安全、数据迁移、失败恢复、用户确认闭环和可追溯健康知识检索。2026-09-21 已新增规则式自动动作识别、训练意图和动作效果语义闭环；主要短板仍是核心 AI 准确率尚未通过真实标注数据验证，开放词汇模型和真正的多 Agent 协作尚未落地。

因此，现阶段适合表述为：

> 基于多模态感知和 Health Agent 编排的个人运动健康管理原型。

在没有数据集评测和完整 Agent 工具循环之前，不应宣传为成熟的专业动作诊断系统或完整多 Agent 平台。

## 二、本轮已经完成的改进

### 1. 打通动作评分长期闭环

新增接口：

- `GET /api/v1/fitness/motion-profile?days=30`
- `GET /api/v1/fitness/motion-history?limit=20`

动作画像聚合以下真实数据：

- 动作质量平均分
- 完成度、稳定性和节奏控制
- 规则偏差指数
- 各动作训练次数、平均分、最佳分和近期变化
- 高频纠正问题
- 样本量、平均置信度和数据质量等级

画像只基于已完成的视频动作评分。样本不足时不会推断力量、耐力、柔韧性或损伤概率。

### 2. 动作画像进入 Agent 上下文

Health Agent 的只读事实层现在包含最近30日动作画像。生成建议和计划时，可以读取用户最近的动作质量、稳定性、节奏和常见问题，而不再只读取饮食、打卡和一般运动时长。

### 3. 小程序展示个人动作成长

动作视频页面新增30日个人动作画像卡片，显示：

- 有效分析次数
- 平均动作质量
- 稳定性和节奏控制
- 不同动作的平均分和近期分数变化
- 数据质量说明

完成一次新的视频分析后，画像自动刷新。

### 4. 修正首页缺失数据误判

此前首页把未记录的睡眠、饮水、步数、饮食和运动按0分参与平均，容易让新用户得到不合理的低分。

现在：

- 未记录项目不参与今日完成度计算；
- 首页显示实际参与计算的指标数量；
- 完全没有数据时显示 `--`；
- 首页名称从笼统的健康指数调整为今日目标完成度；
- 没有饮食记录时，今日计划提示“记录一餐”，不再判断用户蛋白质摄入不足。

### 5. 增加对话连续性

普通健康聊天会读取当前会话最近8条消息，用于理解“那明天呢”“刚才那个动作”等连续追问。历史文本只作为用户上下文，不作为系统指令；数据库仍保存原始用户问题，而不是拼接后的模型提示词。

### 6. 修正风险表达

前端将“风险指数”改为“规则偏差”，避免把二维启发式检测结果误解为损伤概率或医学风险。

### 7. 增加接口限流

登录、聊天、Agent、媒体和Worker接口增加按凭证散列区分的进程内限流，并返回标准 `429` 和 `Retry-After`。该机制可保护单实例和比赛演示环境；多副本生产环境仍应在网关或Redis增加共享限流。

### 8. 增加模型输出安全复核

除用户输入安全检查外，聊天和Agent结果增加一层窄范围的危险指令复核，阻止模型输出自行停药、自行增加剂量、极端节食、催吐和泻药减重等明确不安全建议。输入规则补充了运动后晕厥、无法负重、明显关节肿胀和突发剧烈疼痛等运动红旗表现。

### 9. 将RAG占位实现升级为可追溯知识检索

新增 `knowledge_documents` 权威知识表和 `GET /api/v1/knowledge/search` 检索接口。首批人工审核知识来自WHO、国家卫生健康委员会和CDC，保存标题、机构、真实来源、发布日期、章节、标签和审核时间。

当前实现明确命名为 `audited_lexical_v1`：

- 使用可解释的词法召回和有限查询扩展，不虚构“向量数据库”；
- 命中内容以 `K1`、`K2` 编号进入Agent上下文；
- 模型只能引用检索片段，真实URL由数据库返回；
- 小程序展示来源机构、章节、日期和摘要；
- 无关查询不得返回健康知识卡片；
- DeepSeek不可用时仍可展示带来源的规则降级摘要。

### 10. 建立动作算法可复现评测闭环

新增动作标注规范、批量视频运行工具和自动指标计算器。评测器从固定JSONL标注集与Worker原始预测计算：

- 应评价样本覆盖率与低质量视频拒绝召回率；
- 次数MAE、全部应评价样本的完全正确率和±1正确率；
- 错误提示Micro Precision、Recall、F1及逐错误结果；
- 关键事件F1与时间MAE；
- 算法评分和人工评分的Spearman相关系数；
- 深蹲、俯卧撑和弓步蹲分动作结果。

拒绝评价、缺失预测和处理失败不会从分母中静默删除。报告保存标注与预测文件SHA-256、Worker版本、Python版本、生成时间和当前阈值，能够说明每一个数字对应的具体数据与算法配置。示例数据明确标记为格式演示，不计入比赛结果。

### 11. 建立可执行的动态训练调整规则

新增 `GET /api/v1/fitness/training-adjustment`，综合今日睡眠与主观状态、近7天训练频率、近30天动作画像和画像数据质量，输出调整原因、证据、强度、单次时长上限、恢复优先级和动作技术重点。

该结果不仅进入模型Prompt，还会在模型生成计划后执行确定性约束：

- 今日睡眠少于6小时或状态疲惫时，将今日训练改为轻量恢复；
- 对所有训练项目执行保守时长上限；
- 动作稳定性、节奏或完成度有至少3次样本支持且低于阈值时，将对应技术要求加入首个训练日；
- 高频规则偏差或近期动作分明显下降时，不增加复杂度和负荷；
- 只有动作画像达到高质量且动作表现稳定时，才给出约5%的小幅递进建议；
- 数据不足时返回基础模式，不把缺失记录解释为疲劳、退步或能力不足。

小程序聊天计划卡新增“动态调整依据”，展示置信度、证据和最终实际应用的修改。计划仍需用户确认后才会写入。

### 12. 建立RAG检索量化评测

新增固定查询集规范和 `backend/scripts/evaluate_rag.py`。评测工具直接读取当前数据库中的活跃知识条目，计算：

- Hit Rate@1、Hit Rate@K和MRR；
- 多相关来源的Mean Relevant Recall@K；
- 无关问题拒绝率与误召回率；
- 来源稳定键、标题、机构、HTTPS链接、章节和摘要的完整率；
- 身体活动、营养、慢病和超出范围问题的分类别结果。

报告保存查询集、知识内容快照和检索配置三类SHA-256，可以区分“查询集变了”“知识库变了”和“检索规则变了”。评测文档明确说明检索命中不等于最终回答正确；模型事实正确率和引用支持度仍须对固定回答集进行人工双人评审。

### 13. 自动动作识别v1与安全拒识闭环

小程序动作页默认进入“自动识别”，Worker对同一组MediaPipe关键点分别构造深蹲、俯卧撑和弓步蹲特征序列，使用关节活动范围、身体方向、躯干角度、身体直线度和双膝不对称程度进行可解释匹配。当前实现明确命名为 `rule_feature_matching_v1`，不是LSTM、ST-GCN或经过训练的概率分类器。

识别结果包含：

- 最终识别动作、三个候选的匹配分、候选差值和识别置信度；
- 特征样本不足、关节活动幅度不足、最高匹配分不足或前两名过近时的拒识原因；
- 自动模式和用户手动模式的来源标记；
- 实际评分动作、用户请求动作、识别方法和识别置信度的数据库审计字段。

拒识属于正常完成结果，不会触发错误重试，也不会生成动作评分、关键事件或污染30日运动画像。用户可保留同一视频，在页面选择具体动作后重新分析。后端会拒绝“识别类型与姿态类型不一致”“拒识却产生评分”“自动任务缺少识别记录”等不可信回传。

离线动作评测新增自动识别覆盖率、全样本准确率、已接受样本准确率、逐类F1、Macro-F1和带拒识列的混淆矩阵。`--auto-recognition` 会对固定标注视频隐藏动作真值后运行识别；拒识在全样本准确率和F1中计错，不能靠大量拒识制造漂亮结果。当前只完成模拟特征单元测试和工程闭环，尚未用正式真实视频集得到可对外宣称的识别准确率。

## 四、当前仍未完成

### P0：比赛前必须完成

1. 使用正式微信环境验证 `wx.login`、CloudBase上传、临时链接刷新和删除。
2. 使用真实DeepSeek Key完成对话、计划和失败降级验收。
3. 准备三类真实动作视频标注集，不能只用模拟关键点证明准确率。
4. 重跑MySQL 8.4的0009、0010、0011迁移、全量测试和增量数据保留测试。
5. 准备断网、Worker离线和模型不可用时的演示降级方案及真实录屏。

### P1：建议一周内完成

1. 建立每类至少30–50段的动作测试集，覆盖不同用户、机位、光照、遮挡和动作错误。
2. 使用新增评测器统计次数MAE、关键事件时间误差、错误提示F1、拒绝评价率，以及自动识别覆盖率、Macro-F1和混淆矩阵。
3. 使用两名独立标注者的评分校准 Motion Score 权重，记录标注一致性。
4. 使用新增评测器建立至少50条正式RAG查询；另行完成人工回答事实正确率、引用支持度和无依据陈述率评审。
5. 扩充运动损伤、恢复和常见慢病运动知识，并建立来源过期复审流程。
6. 多实例上线时把当前进程内限流迁移到网关或Redis共享限流。

### P2：数据充分后再做

1. 先使用角度、速度、周期和姿态特征训练轻量动作分类器。
2. 在数据量足够时比较 LSTM、TCN 和 ST-GCN，不以模型名称代替实验结果。
3. 构建经过证据约束的力量、稳定性、节奏和训练习惯画像。
4. 在现有动作画像、睡眠、主观状态和近期训练频率基础上，继续加入计划完成率与用户训练后反馈。
5. 只有在不同 Agent 具备独立工具、职责和可审计运行轨迹后，再升级为多 Agent 架构。

## 五、比赛答辩建议

推荐主线：

```text
动作视频
  → MediaPipe关键点
  → 可解释动作识别（不确定时拒识）
  → 可解释评分与匿名骨骼关键帧
  → 评分和问题持久化
  → 30日个人动作画像
  → Health Agent读取画像
  → 用户确认训练建议
  → 新训练结果继续更新画像
```

知识问答支线：

```text
用户问题
  → 可审计词法检索
  → 权威知识片段 K1/K2
  → Agent有依据地总结
  → 小程序展示真实来源卡片
```

需要主动说明：

- 当前评分是二维可解释启发式模型，不是医学诊断。
- 当前自动识别是二维骨骼规则特征匹配，不是训练模型；候选值是匹配分，不是统计概率。
- 自动识别证据不足时会拒识，用户手动选择是可靠回退路径。
- 匿名骨骼关键帧来自真实视频坐标，但没有保存人物截图。
- 准确率只采用标注数据集的可重复评测结果，不使用人工填写的漂亮数字。

## 六、建议验收指标

|模块|建议指标|
|---|---|
|动作计数|每类动作分别报告 MAE 和完全正确率|
|关键事件|最低点/完成点平均时间误差|
|错误提示|Precision、Recall、F1，不只报告Accuracy|
|动作评分|与人工评分的 Spearman 相关系数和等级一致性|
|低质量视频|拒绝评价准确率，防止系统强行给分|
|RAG|引用正确率、来源覆盖率、无依据陈述率|
|安全|高风险输入漏拦截率与正常问题误拦截率|
|工程|端到端成功率、任务延迟P50/P95和离线恢复成功率|

## 七、最终定位

项目下一阶段不应继续堆叠页面，而应围绕三项工作投入：

1. 用真实数据证明动作分析可信；
2. 让动作历史真正影响训练建议；
3. 用查询集持续验证并扩充权威知识检索。

完成这三点后，项目的核心竞争力才能从“功能完整”提升为“AI能够持续理解、验证并优化用户训练状态”。
