# HealthMate 3.0 系统级更新

> 更新日期：2026-09-21  
> 目标：从“技术能力集合”升级为可连续演示、可解释、可确认的健康行动产品。

## 1. 本轮产品主线

首页只回答一个问题：**用户现在最值得做什么？**

后端把今日健康数据、三项计划、连续记录、AI Worker 能力、任务状态、最近动作评分和识餐状态聚合为一个“健康指挥中心”读模型。小程序根据真实状态优先展示：

1. 正在处理的动作或识餐任务；
2. 尚未补齐的身体状态记录；
3. 尚未记录的饮食；
4. 尚未完成的运动；
5. 剩余计划或趋势复盘。

这让比赛演示不再依赖讲解者手动在多个入口之间跳转。

## 2. 后端更新

新增 `GET /api/v1/health/command-center`，一次返回：

- `today`：今日饮食、运动、睡眠、饮水、步数与目标；
- `plan`：今日三项行动及完成状态；
- `streak`：连续记录；
- `focus`：当前首要行动、理由、按钮和小程序路由；
- `data_quality`：已观察数据源、覆盖维度和只基于已记录数据计算的完成度；
- `ai_system`：本机分析服务、动作能力、识餐能力和活动任务；
- `latest`：最近动作评分和识餐会话摘要。

接口不调用大模型，状态与优先级由确定性规则产生，保证首页稳定、快速、可测试。

## 3. 食物视觉识别更新

识餐结果从“菜名 + 单点热量”升级为证据优先协议：

- `visible_items`：图片中实际可见的食材或菜品；
- `portion_basis`：份量判断依据；
- `calorie_range_low/high`：热量估算区间，点估计必须位于区间内；
- `uncertainty_reasons`：油盐、隐藏配料、重量、遮挡等无法由图片确认的因素；
- 低置信度继续强制提示人工校正；
- 用户确认前不写入正式饮食记录。

旧识餐结果缺少新字段时，小程序提供保守兼容展示，不影响历史任务恢复。

## 4. 小程序视觉与交互更新

新的视觉语言采用暖灰背景、低饱和深绿、纸面卡片和编辑式排版，减少大面积渐变、荧光色、装饰性星芒、英文大写标签和模型术语。

首页重构为：

1. 一个明确的首要行动；
2. 今日完成度与数据覆盖；
3. 运动、饮水、睡眠三条核心进度；
4. 动作分析与拍照识餐两个智能入口；
5. 可直接勾选的今日三件事；
6. 最近动作结果和健康助手入口。

识餐页新增证据、热量区间和不确定性展示；动作页将“本机 Worker、Pose Engine”等工程语言降级为面向用户的“分析服务、姿态证据”。

## 5. 验证结果

本轮本地回归：

- 后端：`90 passed`；
- AI Worker：`74 passed`；
- 小程序 Node 自动测试：`7 passed`；
- 新增指挥中心接口覆盖无数据状态、活动任务状态和 Worker 能力状态；
- 本轮修改的后端与 Worker 产品文件通过 Ruff 检查和格式检查；
- 小程序关键 JavaScript 文件通过语法检查，`app.json` 可解析。

测试不等同于真实微信端、真实云托管和真实视觉模型验收。发布比赛版本前仍需在微信开发者工具与两台真机上完成完整流程。

## 6. 上线顺序

1. 部署后端新版本；本轮无数据库迁移。
2. 验证 `/health/live`、`/health/ready` 和登录后 `/api/v1/health/command-center`。
3. 重启本机 AI Worker，使新的识餐提示协议生效。
4. 上传小程序体验版，清除旧编译缓存后检查首页、识餐和动作页。
5. 用真实账号完成“视频上传 → 云端任务 → 本机分析 → 结果回传 → 首页最近结果”。
6. 用真实餐食完成“拍照 → 证据与区间 → 人工校正 → 确认入库 → 首页更新”。

## 7. 比赛现场建议展示顺序

先展示首页根据缺失数据给出首要行动；完成一次健康记录后返回首页，让首要行动自动变化。随后进入动作分析，强调“训练意图由用户确认、视频只提供可观察证据”；最后进入识餐，现场校正一个模型无法确认的字段并保存。这样能同时展示产品闭环、端云协同、可解释性和人在回路，而不是只展示模型输出。
