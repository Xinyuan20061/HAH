# HealthMate 评审视角审计与升级路线（2026-09-24）

> 本文使用内部模拟评分框架，便于发现答辩短板，不代表任何赛事官方评分标准。分数只依据仓库内可复核材料与本地实测；未完成真机/生产验收的项目不计满分。

## 一、结论先行

HealthMate 已具备“完整健康管理产品 + 多模态分析 + 可审计健康 Agent”的作品体量，明显强于只展示聊天或识别 Demo 的项目。当前最大矛盾不是功能数量，而是**后台创新能力没有完整转化为用户可见价值，且真实模型指标与生产环境证据仍偏弱**。

本轮升级前，Agent v3 已能发现运动断档、睡眠不足、动作表现下滑、体重连升和记录空白，但小程序没有入口；Agent v2 已返回决策轨迹，但聊天页没有展示。评委实际操作时会把这两项核心创新误判为普通问答。因此，本轮优先完成“能力前台化”，而不是继续堆叠新模型名词。

## 三、最可能被评委追问的问题

1. **与普通健康聊天机器人有什么不同？**
   - 回答重点：系统会主动扫描记录并发现变化；不同角色分别处理计划、动作、营养和安全；每条建议展示依据，写入计划前必须由用户确认。
2. **识别准确率有多高？**
   - 动作规则基线必须如实回答 120 段固定集全样本准确率 41.67%、覆盖率 64.17%；不能把“可运行”说成“高精度”。
   - 识餐基线 MAPE 72.70%，定位是“区间估算 + 用户校正”，不是医疗级营养测量。
3. **AI 出错怎么办？**
   - 云端失败静默回落本地/规则；危险输入先安全拦截；低置信结果拒识；计划不自动写入；用户可以导出和删除数据。
4. **是否真的上线与真机验证？**
   - 当前只能展示本地测试与固定集报告；真实微信云托管、最新 MySQL 迁移、CloudBase 权限与真机仍须按验收清单完成。
5. **创新是否只是调用大模型？**
   - 展示确定性主动预警、训练调整规则、动作画像、RAG 来源、多角色路由和操作审计；强调这些在云模型不可用时仍能保留核心能力。

## 四、本轮已完成的大规模升级

### 1. 主动健康提醒前台化

- 新增独立“健康提醒”页面，完整呈现信号、观察依据、保守建议、风险等级和行动入口。
- 首页并行加载主动提醒，不让提醒接口失败拖垮今日指挥中心。
- 个人页增加长期入口；支持下拉刷新、加载骨架、失败重试和无风险空状态。
- 五类信号分别映射到运动、打卡、动作复查和趋势页面，形成“发现—行动”闭环。

### 2. 决策依据可解释化

- 聊天页消费 Agent v2 已返回但此前被丢弃的 `trace`。
- 将技术角色转译为“计划规划 / 运动指导 / 营养建议 / 安全守护”。
- 展示训练调整原因、指导重点与安全护栏变化；没有特殊调整时明确说明使用了哪些用户数据并保留用户确认权。
- 健康提醒可把带上下文的问题送到聊天输入框，由用户确认后发出，不自动替用户提问。

### 3. 质量门禁

- 新增提醒信号到行动路由、未知信号安全降级、异常载荷、页面闭环和聊天解释的自动检查。
- 小程序自动检查从 9 项增加到 19 项；后端 130 项、Worker 90 项继续全绿。
- 同步修正文档中的测试数与迁移 head 漂移，避免答辩材料互相矛盾。

### 4. 人在回路与真实回答评审

- 用户可对主动提醒标记“有帮助 / 不准确 / 已处理”，反馈只进入质量评测，不改健康记录、不自动训练。
- 评测面板展示真实反馈样本量、有帮助率与分布；无样本时明确显示暂无样本。
- 新增 33 案例 × 2 评审空白模板和汇总工具，强制每案例两名不同评审、五维 1–5 分及严重错误标记。
- 双人评审未完成前不会生成正式报告，避免用结构测试替代在线回答质量。

## 五、后续更新方案

### P0：决赛前必须完成（决定作品可信度）

1. 在生产 MySQL 备份上验证 `0018_seed_knowledge_documents` 的 fresh / incremental / repeat 迁移。
2. 用两个真实微信账号验证登录、CloudBase 文件隔离、上传、临时地址刷新、导出与删除。
3. 对固定 33 条 Agent 回答做双人事实核查、引用支持度和有害建议评分；保留评审表与签名日期。
4. 准备“在线主流程 + 断网/停 Worker 降级 + 录屏备份”三套演示路径。
5. 在微信开发者工具和至少两台真机上完成 WXML/WXSS、相机相册权限、安全区和弱网验收。

### P1：高收益增强（时间允许优先）

1. 为主动提醒增加用户反馈闭环（有用 / 不准确 / 已处理）；若需要持久化，必须用 Alembic 新迁移，不能直接改表。
2. 将评测面板增加 Agent 在线人工评审结果与版本对比，而不是只展示离线结构指标。
3. 增加一键生成匿名演示账号数据的受控脚本，显式标注“演示数据”，杜绝预制结果冒充真实识别。
4. 增加前端可访问性检查：字号、对比度、触控区、动态文字换行和老年用户易读模式。

### P2：模型研发（当前保持暂停）

1. SlowFast 六分类微调只有在用户明确恢复训练后执行；真实固定集 Top-1 未达到 85% 不激活。
2. Food-101 候选层只有在同一 42 图固定集上显著改善 MAPE 后启用。
3. 保留旧基线报告用于对照，任何新结果必须带数据清单、哈希、样本量和失败样本分析。

## 六、建议的 3–5 分钟答辩主线

先用 20 秒说明痛点：健康工具通常只在用户提问后回答，而且建议依据不可见。随后在首页展示系统主动发现的真实记录变化；进入健康提醒说明“观察到什么、建议先做什么”；点击“问健康助手”，展示不同角色的建议与“为什么这样建议”；生成计划后由用户确认写入。最后用评测页和离线回落说明：作品不靠一段预制回答，而是有固定集、审计轨迹、安全边界和降级能力。

这条主线比逐页介绍功能更有辨识度，也能在有限时间内同时覆盖产品价值、技术创新、可信 AI 与工程稳定性。
