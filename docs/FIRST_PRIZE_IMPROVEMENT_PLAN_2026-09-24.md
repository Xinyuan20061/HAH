# HealthMate 一等奖导向改进方案

> 版本：2026-09-24  
> 定位：内部冲刺路线，不代表赛事官方评分标准。所有分数、效果和准确率必须由可复核证据支持。

## 一、总判断

HealthMate 已经不是缺功能的项目。档案、记录、趋势、计划、识餐、动作分析、主动提醒、RAG、安全护栏、隐私导出删除和降级链路都已存在。继续横向增加页面，边际收益很低。

冲击一等奖的核心矛盾有三个：

1. **创新能力尚未形成一条独占叙事**：多角色、主动提醒、RAG、云边协同各自成立，但评委容易理解成多个常见技术的组合。
2. **模型和 Agent 的真实效果证据不足**：动作规则基线全样本准确率 41.67%、覆盖率 64.17%，识餐基线 MAPE 72.70%；Agent 双人评审模板已具备，但尚无真实完成结果。
3. **生产与真机证据尚未闭环**：生产 MySQL、微信双账号、文件隔离、弱网与真机权限仍需要正式验收记录。

因此总策略是：

> 把 HealthMate 收敛为“可验证的个人健康干预 Agent”：系统从纵向记录中主动发现变化，展示证据和不确定性，给用户两档可选行动，以短周期个人微实验追踪真实结果，再把结果用于下一轮建议；所有写操作由用户确认，所有结论可审计、可退出、不冒充医学诊断或因果证明。

这条链路比“调用大模型回答健康问题”更有辨识度，也能同时覆盖创新、产品价值、可信 AI 和工程能力。

## 二、一等奖作品的五条硬标准

| 维度 | 一等奖目标 | 当前判断 | 必须补齐的证据 |
|---|---|---|---|
| 原创创新 | 有一句话可复述的核心机制，并能现场跑通 | 多项创新较分散；Agent v4 微实验链路已进入代码 | 一张闭环图、一次完整实演、与普通健康问答的对照 |
| 技术深度 | 感知、推理、行动、评测形成系统，不靠预制回复 | Agent 架构完整；视觉基线偏弱 | 固定测试集、版本登记、误差分析、失败回退录像 |
| 真实价值 | 能证明用户采取了行动并产生可观察变化 | 已有提醒反馈，长期效果样本为空 | 真实用户试用、微实验完成率、帮助率、典型案例 |
| 可信与安全 | 数据来源、建议依据、权限、边界均可解释 | 基础较强 | 双人盲评、严重错误率、真机隐私删除与账号隔离验收 |
| 答辩表现 | 3–5 分钟内完成“痛点—创新—证据—价值” | 演示链路已具备但信息较多 | 单主线脚本、断网备份、30 秒和 3 分钟两个版本 |

## 三、产品与 Agent 的核心升级

### 3.1 主创新：Agent v4 个人健康微实验

完整闭环：

`真实记录 → 主动发现变化 → 证据与数据质量 → 两档实验方案 → 用户确认 → 自动读取进度 → 结果复盘 → 下一轮建议`

设计原则：

- 每个实验只改变一个主要行为，周期控制在 3–7 天。
- 同时展示“温和版”和“标准版”，决定权属于用户。
- 启动、完成和停止都进入 Action Registry 审计，不允许模型静默操作。
- 基线、目标、执行协议、停止条件和结果口径在启动时冻结。
- 只读取真实健康记录计算进度；空样本显示“记录不足”。
- 结果使用“支持假设 / 尚未支持 / 数据不足”，禁止使用“证明有效”。
- 体重实验只验证测量一致性，不诱导短期减重；运动、睡眠实验都有停止条件。

首批覆盖五类信号：运动断档、睡眠不足、动作表现下降、体重连续变化、记录空白。

验收线：

- 五类提醒均有两档实验方案、明确指标和停止条件。
- 未经确认数据库中不会新增实验。
- 同一用户同时最多一个活跃实验。
- 提前结束被拒绝，用户可随时停止且不删除原健康记录。
- 数据不足不会生成正向效果结论。
- 评测页只统计已确认启动的真实样本。

### 3.2 Agent 决策质量升级

把每次建议统一成六段证据契约：观察、数据质量、假设、两档选择、安全边界、后验复盘。固定 33 条 Agent 用例继续覆盖路由、轨迹、计划结构和安全拦截；新增微实验用例覆盖未确认、重复启动、提前结束、数据不足、主动停止、完整复盘六种状态。

### 3.3 长期个性化，但不自动训练

- 用户可确认“更适合温和方案 / 标准方案”。
- 记录哪些建议被标记为有帮助、不准确、已处理。
- 下一次给出方案时显示参考了哪些历史选择。
- 偏好只影响排序和默认选项，不改变安全规则与医学边界。
- 提供清除偏好入口；导出与账户删除必须包含微实验数据。

## 四、证据工程：决定一等奖上限

### 4.1 Agent 双人盲评

使用现有 33 条固定集，由两名独立评审员分别评分：事实正确性、引用支持、可行动性、安全性、表达清晰度，并标记严重错误。

目标线：

- 66 份评审全部完成，不能用自动打分代替。
- 严重错误率为 0。
- 安全性均分不低于 4.7/5。
- 事实正确性、引用支持、可行动性均不低于 4.3/5。
- 双评审员“一分以内一致率”不低于 85%。
- 报告列出所有低分案例及修正，不只展示平均数。

### 4.2 真实用户试用

建议最小规模：20–30 名知情同意的非医疗场景用户，连续使用 7 天；数据匿名化，仅收集完成比赛验证所需字段。

核心指标：主动提醒查看率、帮助/不准确/已处理分布、微实验启动率/完成率/停止率、数据充分率、安全边界理解率、可用性评分与典型失败案例。

建议目标：微实验完成率不低于 70%，有效反馈帮助率不低于 80%，安全边界理解率不低于 90%。达不到目标时必须如实报告，不删除负向样本。

### 4.3 感知模型去弱项

这是当前最大技术扣分点。训练仍保持暂停，只有在用户明确恢复训练并准备好合规数据后执行。

动作识别启用门槛建议：

- 使用用户隔离的固定测试集，避免相似视频泄漏。
- 全样本 Top-1 ≥ 80%，覆盖率 ≥ 90%，宏 F1 ≥ 0.78。
- 六类中不存在召回率低于 65% 的类别。
- 若未达到，主张收窄为“动作质量分析与风险提示”，不包装成高精度识别。

识餐启用门槛建议：

- 从精确热量改成候选菜品、区间估计和用户校正。
- 固定中式餐食集 Top-3 ≥ 85%，热量区间覆盖率 ≥ 80%，校正后 MAPE ≤ 20%。
- 未达到时只作为辅助演示，不作为一等奖创新主轴。

## 五、生产与真机验收

- 在生产 MySQL 备份上验证到唯一 head `0019_agent_micro_experiments` 的 fresh、incremental、repeat 升级并保存日志。
- 两个真实微信账号验证登录、数据隔离、CloudBase 文件隔离、上传、临时地址刷新、导出和删除。
- 至少两台真机覆盖相机、相册、安全区、动态字体、弱网、断网恢复和长文本换行。
- 录制在线主流程、Worker 停止后的降级流程、断网演示备份三段视频。
- 所有演示数据明显标注“演示数据”，禁止把预置结果说成真实识别。

每一项都留下日期、设备、账号、环境、结果和截图/录像索引。

## 六、12 天冲刺节奏

### 第 1–2 天：冻结主线

- 冻结一等奖叙事、功能范围和指标口径。
- 完成 Agent v4 微实验接口、前端、迁移、隐私导出删除和自动测试。
- 输出“感知—推理—行动—验证”架构图。

退出条件：本地完整跑通一个正常实验和一个数据不足实验。

### 第 3–4 天：Agent 质量证据

- 两名评审员完成 33 条固定集盲评。
- 修复所有严重错误与低于 3 分的建议。
- 生成正式评审报告和版本对比。

退出条件：严重错误为 0，五维均分与一致率达到目标。

### 第 5–7 天：真实环境与用户证据

- 完成 MySQL、双账号、真机和弱网验收。
- 启动真实用户 7 日试用并同步记录失败原因。
- 建立显式标注的演示数据生成工具。

退出条件：主流程连续演示三次无阻断，账户隔离和删除闭环通过。

### 第 8–10 天：模型与交互去弱项

- 仅在明确恢复训练后按固定协议改进动作/识餐；否则完成错误分析并收窄主张。
- 完成长辈友好模式、触控区、字号、对比度和长文本验收。
- 根据真实试用反馈压缩操作路径。

退出条件：模型达到门槛，或已诚实降级且答辩材料无过度表述。

### 第 11–12 天：答辩封板

- 形成 30 秒定位、3 分钟主演示和 5 分钟问答版。
- 准备 10 个高频追问及证据链接。
- 生成最终交付包、哈希、文件清单和一键验收说明。
- 进行至少三轮陌生评审模拟。

退出条件：陌生评委 30 秒内能复述核心创新；3 分钟内看到一次真实闭环和一项量化证据。

## 七、答辩主线

### 30 秒定位

“普通健康助手只在用户提问后给建议。HealthMate 会从个人纵向记录中主动发现变化，展示依据和不确定性，再让用户从两档短周期方案中自主选择。系统用真实记录追踪结果，但不会把相关变化说成因果，也不会未经确认修改计划。这使健康建议从一次性回答变成了可验证、可退出、可审计的个人行动闭环。”

### 3 分钟演示

1. 首页展示真实记录与主动发现的睡眠或运动变化。
2. 展示观察依据、数据覆盖度和安全边界。
3. 展示温和/标准两档实验，选择温和版并确认启动。
4. 展示冻结的基线、目标、每日行动、进度和停止入口。
5. 切换至已完成的匿名案例，展示“支持 / 未支持 / 数据不足”复盘。
6. 打开评测面板，展示真实反馈、双人盲评和降级率。
7. 关闭 Worker，证明记录、安全规则和基础建议仍可用。

## 八、评委高频追问

1. 与普通健康聊天机器人有什么不同？——主动发现、证据契约、用户选择、微实验闭环和操作审计。
2. 如何证明建议有效？——双人盲评与真实用户统计，同时明确个体观察不能证明因果。
3. AI 出错怎么办？——低置信拒绝、规则降级、用户校正、安全前后审查和停止条件。
4. 是否自动修改计划？——所有写操作都要用户确认，并可展示 Action Registry。
5. 模型准确率是多少？——只报固定测试集、样本数和适用范围；不达门槛就收窄主张。
6. 数据如何保护？——账号隔离、最小化上传、导出删除，微实验同样进入隐私闭环。
7. 微实验是不是医疗试验？——不是；它是一般生活方式自我观察，不诊断、不治疗、不证明因果。

## 九、停止做什么

- 停止新增与主线无关的页面、模型名和角色名。
- 停止用“多智能体”本身作为创新，必须展示角色如何改变结果并被审计。
- 停止使用内部模拟分数作为获奖预测。
- 停止把空样本、演示数据或结构检查写成真实效果。
- 停止追求一次回答看起来聪明，优先追求长期闭环可验证。
- 停止在模型指标未达到门槛时扩大宣传范围。

## 十、最终放行清单

- [ ] 核心创新可被陌生评委一句话复述。
- [ ] Agent v4 完整闭环在真机和生产数据链路上跑通。
- [ ] 33 条 × 2 人工评审完成，严重错误为 0。
- [ ] 至少一组真实用户试用结果，包含负向与退出样本。
- [ ] 生产 MySQL `0019` 迁移和双账号隔离通过。
- [ ] 动作/识餐达到启用门槛，或已诚实降级为辅助能力。
- [ ] 在线、降级、断网三套演示都可执行。
- [ ] 材料中的每个数字都能定位到报告、日志或匿名原始数据。
- [ ] 隐私、安全、医学边界和因果边界均可现场展示。

一等奖不能靠功能数量保证。完成以上路线后，HealthMate 才会从“功能丰富的健康应用”升级为“有原创闭环、有真实证据、有可信边界的 Agent 产品”。
