# HealthMate 决赛演示主线稿

> 版本：2026-09-24 · 对应 Agent v4「可验证的个人健康干预 Agent」
> 使用前提：演示前先运行 `backend/scripts/seed_demo_account.py` 灌入演示账号（openid `demo-presenter-2026`，昵称已标注「演示账号（数据为演示）」）。所有展示的健康数字均为脚本合成，不是真实测量或真实识别结果——动作分析与识餐在演示中**不展示为高精度识别**。

---

## 一、30 秒定位（开场）

> “普通健康助手只在你提问后才回答。HealthMate 会从你自己的纵向记录里**主动发现变化**，把观察依据和不确定性摆出来，再让你从**温和版/标准版**两档短周期方案里自己选。系统用真实记录追踪结果，但不会把相关变化说成因果，也不会未经确认替你改计划。健康建议因此从一次性问答，变成了**可验证、可退出、可审计**的个人行动闭环。”

---

## 二、3 分钟主演示（按顺序，约 7 步）

| 步骤 | 操作 | 要说的话 |
|---|---|---|
| 1 | 打开小程序「健康提醒」页 | “这是系统主动扫出来的变化，不是我点的。演示账号有三条：运动断档、连续睡眠不足、体重连升。” |
| 2 | 展开任意一条，念出「观察到 / 建议先做」 | “每条都写了观察依据和数据覆盖度——比如近 7 天几天有记录。没有记录就明确说记录不足，不编结论。” |
| 3 | 在「把提醒变成可验证行动」卡片展示温和版/标准版两档 | “同一信号给两档：温和版 3 天、标准版 5 天，只改一个行为，各有停止条件。历史选过温和版会提示‘你之前更常选温和版’，但仍可自由选。” |
| 4 | 选温和版 → 确认弹窗 → 启动 | “注意：不点确认，数据库里不会有任何实验。启动后基线、目标、每日行动在这一刻冻结。” |
| 5 | 切到进行中的实验卡，展示进度条/今天行动/停止按钮 | “进度只读真实健康记录，不用演示值冒充。用户随时可以停止，原来的健康记录一条都不会删。” |
| 6 | 切到一个已完成的匿名案例（或演示到期复盘弹窗） | “复盘只给三种结论：支持假设 / 尚未支持 / 数据不足。下面写着‘这是单用户短周期观察，不证明因果’。” |
| 7 | 打开「评测」面板 | “这里只统计用户确认启动的真实实验数、完成率和结果分布；离线有 33 条固定集和双人盲评模板。” |

**收尾句（30 秒内）**：“从主动发现、两档选择、用户确认，到真实进度追踪和不夸大的复盘——这就是我们的核心闭环。”

### 断网/降级备份（万一现场网络不稳）

- Worker 停止：记录、安全规则、基础建议仍可用（演示文案：“云端大模型不可用时，主动提醒、安全护栏和基础建议不中断。”）
- 完全断网：提前录好三段视频——在线主流程 / Worker 停止降级 / 断网备份——按评委要求切录像。

## 三、5 分钟问答版（高频追问与口径）

1. **和普通健康聊天机器人有什么不同？**
   主动发现（不靠提问）、六段证据契约（观察/数据质量/假设/两档选择/安全边界/后验）、用户确认才写操作、微实验闭环、Action Registry 可审计。
2. **怎么证明建议有效？**
   双人盲评（33 条 × 2，严重错误为 0、安全 ≥4.7）+ 真实用户实验完成率/帮助率。同时明确：个体短周期观察**不能证明因果**。
3. **AI 出错怎么办？**
   危险输入先安全拦截；低置信拒识；云端失败静默回落本地/规则；计划不自动写入；用户可导出删除全部数据。
4. **识别准确率多少？**
   如实报固定测试集：动作规则基线全样本 41.67%、覆盖率 64.17%；识餐 MAPE 72.70%。所以我们把这两项定位为**辅助能力**，不包装成高精度识别；微实验闭环才是主创新。
5. **数据怎么保护？**
   账号隔离、最小化上传、导出含微实验数据、账户删除按外键顺序级联；演示账号数据脚本可一键重置。
6. **微实验是医疗试验吗？**
   不是。它是一般生活方式的自我观察，不诊断、不治疗、不证明因果；有停止条件，不适即停。
