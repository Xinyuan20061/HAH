## 实际实现

### 用户闭环

```text
本人同意与可调低预算
  → 按冻结周期读取当前报告/来源/授权/规则/审核知识版本
  → 只提出已发生且可能改变端点判断的一条问题
  → 确认写入；未知/拒答/不可用只记录交互状态
  → 当前证据充分时签发可重验依据，不直接更新个人信念
  → 来源或知识绑定变化立即阻断旧依据
  → 仅按原槽修复并保留修订历史
  → 预览后经过注册的本人确认动作产生新复查版本
```

### 服务端、持久化和权限

- `backend/app/services/policy_learning/acquisition/` 实现严格请求合同、确定性快照哈希、精确 execution oracle、有界深度规划、问题/响应/预算编排、证书签发与实时核验、修复及维护补偿。
- `backend/app/api/v1/policy_acquisition.py` 接口已接入主路由一次：会话建立/读取、next、answer、暂停/恢复/repair、证书/历史、原观察修复、再复查预览与提案。命令使用 Idempotency-Key；客户端不能提交结论、门槛、槽位或超时事实。
- 首发限定 `session_duration`。执行与配对负担端点分开；负担问题只采集真实已发生的本人 0–10 自评，不从动作/热量推算。unknown/declined/unavailable 不改写个人事实；超时由服务器维护处理。
- `0038_low_burden_evidence_acquisition` 增加取证会话、问题、命令、预算、事件、证书、依赖、证据修订和并发 fence，并为观察引用添加 revision。
- 用户级 fence、行锁/CAS、命令幂等和独立数据库 Session 并发测试覆盖同一周期双 next 竞态；SQLite 下只签发一个有效问题、只计一次预算。目标 MySQL 并发语义仍需在部署方数据库复验。
- 源变更路径在源事务内标记旧观察/裁决/证书不可用；有界维护端点补偿漏接的过期证书/问题并处理 pending outbox。该端点由 worker token 保护，服务部署环境尚无可验证的定时器接线证据。
- 隐私导出/删除注册覆盖新增用户数据表，导出仍排除密钥明文、临时媒体 URL 和媒体二进制；删除按 FK 依赖顺序处理，并通过账号删除测试。

### 取证规划与知识依据

- 生产服务对已到期未知执行槽以及可配对的基线/跟进观察建立候选；先经过本人归属、冻结窗口、来源可解析、拒答/超时冷却和预算门控，再由有限 `choose_next` 规划器决策。问题按稳定候选目标绑定；证据 fingerprint 改变不能重置拒答冷却。
- `SelectedSource` 请求契约和来源解析器保留扩展点，但当前公开的 `session_duration` 模板没有经审核、能直接代表主观负担的现有记录适配器，因此不会生成 `source_selection` 问题。动作时长、热量、睡眠等不能被冒充成主观负担；需要另行审核指标语义及来源窗口后，才可开放该候选。
- Planner 候选最多 12、单问题分支最多 6、深度受限；固定声明先验只影响提问顺序，不改变精确执行证明。互补基线/跟进测试覆盖两步规划与预算耗尽暂缓。
- `knowledge_contract.py` 将模板测量规则、适用范围、排除边界及已审核知识文档的内容摘要、发布日期、审核时间和启用状态纳入版本哈希。内容改变或撤回会使旧证书读取失效并阻止继续使用。RAG 只提供解释依据，不补本人未知事实、不改冻结门槛。
- 检索结果明确标记 `conflict_status=not_assessed`；目前没有语义矛盾自动检测/裁决器。系统不会把多来源并列呈现成共识，冲突时提示未解决并回到审核来源。

### 小程序及交互成本

- 周期页提供明确同意、下调预算、每次一题、本人确认/不记得/拒答/无可用记录、暂停/恢复、日期与本人负担评分、弱网安全重试。
- 问题计时按页面可见片段累积，离页暂停、返回续计，并绑定固定问题 ID。Answer 请求把封顶的 `client_elapsed_ms` 带入原幂等正文；失败重试不重算/改写正文。服务端另记交互计时，拒答和未知也计入成本而不写健康事实。
- 该耗时是客户端报告的交互耗时，不是可信硬件计量、服务器证明的“实际作答时间”或强制限制。基准另以 simulated time 明确标注。
- 复查页提供观察修复目标、版本化修复、证据预览、待确认再复查和历史裁决。Node 页面测试验证合同，不等同微信组件渲染与真机体验验收。
