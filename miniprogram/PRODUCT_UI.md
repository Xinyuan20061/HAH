# HealthMate Product UI System — v1.0 Competition Edition

视觉目标不是“比赛 Demo”，而是轻量、可信、能长期打开的健康产品。

## 设计原则

- 背景使用低饱和灰绿，主要 CTA 使用深绿；AI 关键确认使用有限的荧光绿强调，不扩散到整页。
- 首页优先回答“今天怎么样 / 下一步做什么”，避免功能宫格堆叠。
- 一张卡片只承担一个决策。
- AI 页面强调事实来源、待确认动作和 Safety 状态，而不是复制普通聊天软件。
- 不再以“增加动画数量”作为视觉升级目标。

## 统一数据状态

所有关键数据页应覆盖：

1. `loading`：骨架/Spinner + 正在做什么。
2. `empty`：明确是“没有数据”还是“记录不足”。
3. `error`：解释可恢复原因 + retry。
4. `success`：告诉用户动作真正写到了哪里。
5. `destructive`：删除等不可逆动作必须二次确认。

全局 `app.wxss` 提供 `state-card / state-title / state-desc / state-spinner` 等基础状态样式。

## AI 流程可视化

### AI 识餐

`识别 → 校正 → 确认 → 入库`

### Health Agent

`AI 建议 → 用户确认 → Action Registry → 写入计划`

流程可视化的目的不是装饰，而是让用户知道“AI 现在只是建议，还是已经修改了我的数据”。

## 安全产品页面

“我的 → 隐私与医疗安全”直接连接真实能力：

- 当前数据库 / 媒体存储模式说明
- API Key 保存方式
- 数据导出
- 数据永久删除
- 医疗能力边界

这比单独放一页长隐私条款更适合比赛现场演示产品完成度。
